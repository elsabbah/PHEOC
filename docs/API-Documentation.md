# التكامل وواجهات API

## Push API

المواصفة الآلية في `/openapi.json` (OpenAPI 3.0.3). يلزم `X-Api-Key` صالح عبر HTTPS في الإنتاج، و`Idempotency-Key` بطول لا يتجاوز 128 عند الاستقبال.

```http
POST /api/integration/ebs/events
Content-Type: application/json
X-Api-Key: <configured-secret>
Idempotency-Key: <stable-message-id>
```

```json
{
  "externalEventId": "source-event-id",
  "event": {
    "title": "عنوان الحدث",
    "eventType": "نوع موثق",
    "threatType": "تصنيف موثق",
    "governorateId": 1,
    "confirmedAt": "2026-11-05T08:00:00Z"
  }
}
```

الأمثلة لا تُرسل تلقائياً ولا تمثل بيانات فعلية. معرف المحافظة محلي ويحتاج ربطاً مع كود المصدر. تواريخ النقل UTC أو ISO 8601 بإزاحة؛ مدخلات واجهة التاريخ والوقت موسومة UTC. نقص عدد الحالات أو الوفيات يبقى null ولا يُعتبر صفراً.

نتائج الاستقبال: 201 للإنشاء، 200 لإعادة الرسالة نفسها، 409 لتعارض الهوية أو المحتوى، 400 لبيانات غير صحيحة/غير مؤكدة، 401 لاعتماد غير صالح، و429 لتجاوز المعدل. تُحفظ الرسالة الممثلة بـDTO بشكل مشفر داخل Inbox مع بصمتها، ويُحفظ الحدث وTimeline وOutbox في معاملة واحدة. لا يُعد هذا حفظاً بايتياً للطلب الأصلي أو قبولاً لحقول Metadata غير المعرفة في العقد.

`GET /api/integration/ebs/events/{publicId}` يعيد المصدر والمعرف الخارجي والحالة ووقت الاستلام دون التفاصيل الصحية. `POST .../{publicId}/status` يضع تحديث الحالة في Outbox دون تغيير حالة الحدث. لا تؤكد 202 التسليم. التحديث الفعلي للحالة يتم عبر إجراءات تشغيل مفوضة.

## موصل EgyptEBS الفعلي

`Infrastructure/Services/EgyptEbsReader.cs` يستخدم اتصال قراءة منفصلاً واستعلامات parametrized على المخطط المفحوص في SQL Server 2016. شروط القبول: الإشارة غير محذوفة، آخر Verification غير محذوف له YesNo.Code=YES، وآخر Triage غير محذوف له Relevance.Code=IN. لا يعتمد على رقم ثابت لقيمة «نعم» أو «يدرج».

| المصدر | الوجهة / السياسة |
| --- | --- |
| Signals.Id | ExternalEventId تحت المصدر EgyptEBS |
| Verifications.Id | جزء من مفتاح رسالة المصدر |
| SignalTypes.NameAR وSignalCategoryCodeTables.NameAR | نوع الحدث والتهديد |
| SignalLocations → AdministrativeLevels وصولاً إلى GV | محافظة موقع الحدث؛ لا تستخدم محافظة المبلّغ كبديل |
| Signals.EventStartDate | بداية الحدث المصدرية، وليست تلقائياً تاريخ النشوء المعتمد لـ7-1-7 |
| Signals.DetectionDate | اكتشاف الإشارة |
| Verifications.Date | تحقق/تأكيد الإشارة |
| CreatedAt في المصدر | لا يُنسخ إلى تاريخ الإخطار |
| موصل الاستقبال الحالي لا ينسخ تاريخ الإخطار إلى الحدث | NotifiedAt يبقى null؛ شاشة المؤشر تقرأ أول Responses.CreatedAt عند مراجعة قيد 7-1-7 كما أدناه |
| لا مصدر أعداد حالات/وفيات معتمد في هذه الجداول | الأعداد تبقى null |

توقيت المصدر يفسر وفق Egypt Standard Time استناداً إلى المصدر البرمجي المفحوص، ويُحوّل إلى UTC؛ التوقيت الغامض أثناء الانتقال الصيفي يحتاج مراجعة ولا يُفترض. يتم ربط أسماء المحافظات بعد توحيد الهمزات/الياء والمسافات؛ أي اسم غير مربوط يُرفض بدلاً من اختيار محافظة بديلة.

الاستقبال اليدوي من `/EgyptEbs`. الاستقبال التلقائي اختياري بنقطة بدء ومؤشر تقدم محفوظ. لا تُكتب حالة PHEOC داخل جداول EgyptEBS؛ رد الحالة عبر HTTP يحتاج عنواناً فعلياً وعقداً مع الجهة المالكة، وغير مهيأ حالياً.

## جلب تواريخ 7-1-7 من EgyptEBS — source-map-v2

`GET /Analytics/SourceDates/{eventId}` يتطلب Reports.View ونطاق الحدث، ويستخرج SignalId من Inbox المحلي بدلاً من قبول معرف إشارة حر من المتصفح. يقرأ من اتصال المصدر الحالي (بما فيه إعداد الخادم والحساب المشفر) دون كتابة. يعيد Signals.EventStartDate مرشحاً لتاريخ النشوء وSignals.DetectionDate للاكتشاف، بصيغة date وفق تاريخ المصدر المحلي دون تحويل عبر UTC أو توقيت الجهاز. الاستخدام في حقول المؤشر يتطلب مراجعة المستخدم وحفظ قيد جديد؛ لا يؤدي الجلب إلى حفظ أو تغيير البسط والمقام أو الاستبعاد أو السجلات السابقة.

وفق توضيح المستخدم الأخير في 2026-11-07، **أقدم Responses.CreatedAt غير محذوف هو تاريخ إخطار أول جهة مسؤولة عن الاستجابة**. يُربط عبر Responses.SignalId، ويُرتب حسب CreatedAt ثم Id، وتؤخذ قيمة date من توقيت المصدر المحلي دون تحويل بتوقيت الجهاز. تبقى IsConfirmed ظاهرة كحالة مصدر دون إضافتها شرطاً جديداً للاختيار. الدليل يحفظ رقم سجل Responses وطابعه الزمني وحالة التأكيد وإصدار المضاهاة source-map-v2. عند غياب الاستجابة أو تعذر قراءتها يبقى Notification غير متاح ولا يستبدل بتاريخ التحقق أو استلام المركز. تواريخ إجراءات الاستجابة السبعة تحتاج مضاهاة مستقلة. يحل هذا التعريف محل تفسير source-map-v1 السابق؛ القيود السابقة لا يعاد تعديلها.

قراءة Responses تحتاج إذن SELECT مستقلاً إذا لم يكن متاحاً لحساب المصدر. حساب الاتصال الحالي نجح في القراءة أثناء التحقق، ولم تُنفذ GRANT أو تعديلات على المصدر. لا يوسع التطبيق الأذونات تلقائياً؛ إذا رفضت قراءة Responses تبقى تواريخ Signals متاحة وتظهر رسالة تخص صلاحية القراءة. منهجية الحساب باقية `717-alliance-2024/date-difference-v1`، وإصدار مضاهاة المصدر مستقل ومثبت في نص الدليل `source-map-v2`.
