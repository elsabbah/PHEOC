# البحث والفلترة وصفحات استقبال EgyptEBS

صفحة `/EgyptEbs` تتيح البحث برقم الإشارة كاملاً (مع أو دون #)، أو بنص في النوع أو الفئة أو وصف الإشارة أو عنوانها أو المحافظة. تُعامل علامات البحث مثل % و_ كحروف حرفية، ولا تُدخل في SQL كنص تنفيذي.

الفلاتر: المحافظة والنوع وحالة الاستقبال (الكل، لم يتم استقبالها، تم استقبالها)، وتاريخ التحقق من/إلى. نطاق التاريخ يشمل اليوم الأخير كاملاً ويخص توقيت التحقق كما يعرضه المصدر. الضغط على **بحث وتطبيق الفلاتر** يبدأ من الصفحة الأولى. **مسح الفلاتر** يعيد العرض الافتراضي. عدد النتائج في الصفحة 20 أو 50 أو 100، والافتراضي 50.

يعرض الكارت العدد الكلي المطابق والنطاق الظاهر، مع صفحات مرقمة وروابط الأولى والسابق والتالي والأخيرة. ترتيب النتائج تنازلي حسب رقم الإشارة، ولا تقتصر الفلترة على الصفحة المعروضة. إذا طلب رابط صفحة تتجاوز آخر صفحة يضبط العرض على الصفحة الأخيرة؛ وعند عدم وجود نتائج يعرض صفحة واحدة فارغة برسالة واضحة.

تُحفظ الاختيارات في عنوان GET؛ روابط الصفحات والتحديث التلقائي تحتفظ بنفس البحث والفلاتر وحجم الصفحة ورقمها. لا يستبدل التحديث نموذج الفلاتر أثناء تحريره. يظل رابط `before` القديم مدعوماً إذا فتحه مستخدم من رابط محفوظ. وصول إشارات جديدة قد يغيّر العدد وترتيب حدود الصفحات في التحديث التالي.

التنفيذ في `EgyptEbsReader.Browse` ضمن `EgyptEbsBrowse.cs`. يتم تحديد أحدث تحقق وأحدث فرز غير محذوفين بواسطة ROW_NUMBER أولاً، ثم اشتراط YES وIN، ثم تطبيق الفلاتر وحساب COUNT OVER قبل تحديد الصفحة. لا تُستخدم سجلات تحقق أو فرز أقدم لمجرد أنها تطابق الفلتر. تجلب تفاصيل الإشارات بعد تحديد صفوف الصفحة لتقليل العمل على النصوص الكبيرة. البحث الرقمي يستخدم معرفاً صحيحاً محدداً. جميع القيم معاملات SQL؛ الأجزاء المتغيرة من بنية الاستعلام ثوابت في الكود.

حالة الاستقبال مصدرها InboxMessages في PHEOC_OMS. تمرر معرفات الإشارات المستقبلة إلى استعلام مصدر EgyptEBS بمعامل XML واحد عند الحاجة، حتى تعمل الفلترة قبل التقسيم دون ربط عابر لقواعد البيانات أو الاعتماد على حد معاملات IN. لا يشترط OPENJSON أو إضافة كائنات في المصدر. الفلترة والجلب SELECT فقط؛ لا جداول أو فهارس أو صلاحيات جديدة. بوابة التفويض المركزية نفسها مطبقة على الصفحة وجزء التحديث.

يظل عامل الاستقبال التلقائي يستخدم ReadChanges والاستعلام السابق بدفعات 50 ونقطة تقدم؛ لا تتحكم فلاتر الشاشة في نطاق الاستقبال التلقائي. لا تغيّر الفلاتر تفعيل الاستقبال أو بيانات المصدر أو سجلات الأحداث المستقبلة. يستمر تمييز الاستقبال الجديد وحركة الكارت دون إعادة مدة التلاشي عند استبدال الجدول.

التحقق: اختبار SQL Server الفعلي راجع الصفحات المتتابعة دون تكرار، والبحث عن إشارة من صفحة لاحقة، والمحافظة والنوع والتاريخ، والمدخلات الحرفية، وعدم النتائج، والصفحة خارج النطاق، وحالتي الاستقبال بعد إدخال ضمن معاملة Rollback. اختبار HTTP يؤكد تمرير الفلاتر نفسها إلى الصفحة وجزء التحديث. نجحت اختبارات التكامل الـ63 دون تخطي. فحص متصفح حي للقراءة فقط راجع البحث والصفحات ومسح الفلاتر والمحافظة وحالة الاستقبال وحفظ معاملات التحديث وRTL عند 390 بكسل دون أخطاء JavaScript أو Console. الأدلة في `artifacts/browser/egypt-ebs-browse-*` و`browser-egypt-ebs-browse-check.mjs`. اختبار التمييز السابق نجح أيضاً بعد التغيير، باستخدام ردود متصفح محاكاة دون أحداث دائمة.

## طريقة العرض والتاريخ الافتراضي

داخل قسم **الإشارات المؤكدة والمدرجة** استخدم **عرض جدولي** أو **كروت**. يتغير التخطيط لنفس الصفحة والنتائج والفلاتر. تحتفظ روابط الصفحات والتحديث التلقائي بالعرض المختار؛ الكروت تقدم نفس إجراء الاستقبال وتستمر فيها حركة الوصول والتمييز لخمس ثوانٍ. يُعرض وصف المصدر في ثلاث سطور مرئية للحفاظ على ترتيب الكروت.

عند فتح الشاشة دون فترة محددة، يكون **تاريخ التحقق من أمس إلى اليوم بتوقيت مصر**، شاملاً اليوم الأخير. يمكنك اختيار فترة أخرى، أو مسح حقلَي التاريخ ثم تطبيق الفلاتر لعرض كل الفترات. يبقى اختيار الفترة المخصصة أو الفارغة أثناء التبديل والتنقل والتحديث. «مسح الفلاتر» يعيد العرض الافتراضي والتاريخ الافتراضي. لا تؤثر هذه التواريخ في عمل الاستقبال التلقائي.
