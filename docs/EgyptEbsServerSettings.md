# تغيير عنوان خادم EgyptEBS

من **الإعدادات ← خادم EgyptEBS**، أو رابط الإعدادات في صفحة استقبال EgyptEBS:

1. أدخل اسم الخادم، أو `SERVER\INSTANCE`، أو عنواناً ومنفذاً مثل `192.168.1.10,1433`.
2. اضغط **اختبار الاتصال** لفحص الاتصال وصلاحية قراءة جداول المصدر دون حفظ.
3. اضغط **اختبار وحفظ العنوان** لإعادة الاختبار وحفظ العنوان عند نجاحه.

يظل اسم القاعدة `EgyptEBS` وإعدادات تشفير الاتصال كما هي. يستخدم التطبيق حساب القراءة الحالي ما لم تدخل حساب SQL بديلاً وكلمة مروره معاً في القسم الاختياري. اترك الحقلين فارغين للاحتفاظ بالحساب المحفوظ، أو اختر حساب إعداد التشغيل الأصلي لإلغاء البديل. لا تُعاد كلمة المرور في الصفحة بعد الاختبار أو الخطأ؛ عند اختبار حساب جديد ثم حفظه يجب إعادة إدخال كلمته. لا تسمح الشاشة بإدخال Connection String. تغيير العنوان مخصص لنقل عنوان المصدر نفسه؛ لا يغيّر هويات الإشارات المستلمة أو نقطة التقدم أو حالة تفعيل الاستقبال.

يطبق العنوان في الاتصالات التالية للقارئ اليدوي والتلقائي دون إعادة التشغيل؛ قد تنتهي دورة بدأت قبل الحفظ على اتصالها السابق. لا يغيّر الإعداد اتصال قاعدة التطبيق PHEOC_OMS. اختبار القراءة يستخدم SELECT TOP (0) للتحقق من الجداول العشرة وأعمدتها، ولا ينشئ مستخدمين أو يمنح صلاحيات أو يكتب في المصدر. فشل الاختبار يمنع الحفظ ويُبقي العنوان السابق. يوجد تحقق من صلاحية Admin.Settings والنطاق المركزي وAnti-forgery، وتُرفض مدخلات حقن سلسلة الاتصال.

العنوان البديل يحفظ في `.local/settings/egypt-ebs-server.json` داخل مجلد تشغيل Web، مع معرف نسخة ووقت التعديل UTC والمستخدم. الملف لا يحتوي بيانات دخول صريحة أو سلسلة اتصال؛ الحساب البديل، عند حفظه، يحفظ كحمولة مشفرة بواسطة ASP.NET Core Data Protection بغرض مخصص للتكامل. الملف مستبعد من Git وحزمة النشر. يقرأه الموصل عند إنشاء الاتصال؛ عدم وجوده يستخدم عنوان إعداد التشغيل الأصلي. يُرفض حفظ نموذج قديم بعد تعديل أحدث. الحفظ باستبدال ملف ذري مع تسلسل عمليات الكتابة داخل العملية.

على التشغيل الفعلي: احفظ مجلد الإعدادات المحلي عند تحديث نسخة النشر، وأعط هوية التطبيق حق القراءة والكتابة إليه. صُمم المخزن المحلي لنسخة تطبيق واحدة؛ إعداد عدة عقد يحتاج مخزناً مشتركاً وتنسيقاً مناسباً. عند استخدام حساب بديل، احفظ مفاتيح Data Protection وهوية التشغيل مع الإعداد لاستعادته؛ مفاتيح التشغيل محمية بـDPAPI على Windows. بيانات حساب إعداد التشغيل الأصلي تبقى في Secrets/Environment. لا تضمن الحزمة إعدادات الخادم المحلي.

التحقق: 11 حالة جديدة تشمل حفظ العنوان وإعادة قراءته من مخزن جديد، استخدامه في مصدر الاتصال دون إعادة التشغيل، منع التعارض، بقاء خصائص الأمان وبيانات الدخول، فشل الاختبار دون حفظ، الصلاحيات، وPOST الحقيقي مع CSRF. نجحت اختبارات التكامل الخمسون دون تخطي. فحص المتصفح على النسخة الحية اختبر SQL الحالي للقراءة فقط، وعدم عرض بيانات الدخول، ورفض إدخال غير صالح، والعرض بعرض 390 بكسل دون أخطاء JavaScript. لم يُغير الفحص عنوان الخادم الفعلي؛ حفظ عنوان بديل تم داخل مخزن اختبار معزول. الأدلة: `artifacts/browser/egypt-ebs-server-*` والسكربت `scripts/browser-egypt-ebs-server-check.mjs`.

## تشخيص رفض الاتصال — 2026-11-06

فُحص العنوان المطلوب 192.168.34.227,1433، ورد SQL بالرمز 18456: رفض حساب القراءة الحالي. هذا يثبت الوصول إلى SQL ولا يثبت صلاحية الحساب على هذا الخادم. لا ينشئ التطبيق حسابات أو يمنح صلاحيات؛ يلزم حساب موجود ومخول بالقراءة على EgyptEBS. الرسائل تفرق الآن بين رفض الحساب، تعذر فتح القاعدة، نقص SELECT، ومخطط مفقود أو غير متوافق، دون عرض التشخيص الخام أو كلمات المرور.

التحقق الحالي: 17 حالة للإعدادات و56 اختبار تكامل ناجحة دون تخطي. يشمل اختبار الحساب البديل تشفيره وعدم ظهوره في الملف أو HTML، وفكّه بمزود حماية جديد باستخدام المفاتيح المحفوظة، وإعادة استخدامه، وإرجاع الحساب الأصلي، ومنع الحفظ عند الفشل. اختبار متصفح حي أعاد خطأ 18456 للعنوان المطلوب بالرسالة المحددة؛ ولم يُحفظ عنوان جديد أو حساب تشغيل جديد أثناء الفحص. الصورة: artifacts/browser/egypt-ebs-auth-failure.png.

رمز SQL 5 أو 10013 أثناء فتح الاتصال قد يعني رفض Windows لاتصال الشبكة من عملية التطبيق. نجاح Test-NetConnection في جلسة أخرى لا ينفي ذلك؛ شغّل التطبيق من جلسة Windows المعتادة دون قيود شبكة أدوات التطوير. مهلة اختبار SQL الآن 20 ثانية، والسقف الإجمالي 30 ثانية، ويُميز انتهاء المهلة -2 عن رفض الحساب 18456. لا يُعد نجاح TCP دليلاً على اكتمال مصافحة SQL أو صحة بيانات الدخول.
