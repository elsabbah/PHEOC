# التشغيل والنشر

## بيئة التطوير التي تم التحقق منها

Windows x64، SDK 10.0.201، التطبيق net10.0، EF Core/Identity 10.0.9، SQL Server 2016 بالإصدار 13.0.1601.5، قاعدة PHEOC_OMS بمستوى توافق 130. فحص الحزم كشف اعتماد Pkcs 9.0.4؛ عولج بتثبيت 10.0.13 مباشرة. لا يعني هذا تحديث Runtime المثبت على الجهاز.

الأسرار المحلية في User Secrets بالمعرف `PHEOC-OMS-PHEOC2-Development`. يحمل المضيف أسرار التطوير عند `ASPNETCORE_ENVIRONMENT=Development`. حساب SQL `pheoc_oms_app` ليس sysadmin، وله قراءة/إضافة/تعديل داخل قاعدة التطبيق، مع منع تعديل وحذف السجلات الدفترية الحساسة. حساب التهيئة الإداري لا يُستخدم لتشغيل التطبيق.

## تهيئة قاعدة التطبيق

`scripts/Initialize-Development.ps1` ينشئ PHEOC_OMS إن لم توجد، ويرفض تطبيق مخطط أولي فوق قاعدة ذات مخطط غير معروف، ويطبق migrations صراحة، ثم ينشئ البيانات المرجعية والأدوار والمدير. لا يتضمن بيانات تشغيل تجريبية ولا يحذف قواعد أو جداول. يمكن إعادة تشغيله مع الاحتفاظ بالأسرار الموجودة؛ لا يستخدم كأداة إعادة تعيين كلمات المرور.

`database/001-InitialSchema.sql` سكربت migrations كامل مع فحوص تاريخ التطبيق، جاهز للمراجعة والتشغيل داخل PHEOC_OMS الموجودة عبر SSMS. لا ينشئ القاعدة أو حسابات Identity/البيانات المرجعية؛ سكربت التهيئة يتولى ذلك. لا تطبق Down migrations على بيانات تشغيل دون مراجعة ونسخة احتياطية.

لم يُشغّل هذا الملف مباشرةً في SSMS؛ تطبيق المخطط الفعلي تم بواسطة EF Migrate في أمر التهيئة الصريح.

## اتصال EgyptEBS

تم فحص المخطط والمصدر الفعليين وتفعيل **SELECT فقط** على الجداول العشرة في `database/002-EgyptEBS-Reader.sql` بعد موافقة المستخدم. لا يغير هذا السكربت بيانات المصدر أو بنيته. لإعداد بيئة أخرى بعد الموافقة المناسبة:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/Enable-EgyptEbsReader.ps1
```

يحفظ الاتصال باسم `ConnectionStrings:EgyptEbsReader`. حساب المصدر لا يملك INSERT أو UPDATE أو DELETE على Signals؛ تم التحقق من صلاحياته فعلياً. لا تُعدّل ملفات مشروع EgyptEBS أو مخططه عند تطوير الموصل.

المزامنة التلقائية متوقفة افتراضياً. تفعيلها من صفحة استقبال EgyptEBS يحدد نقطة بدء محلية، ثم يفحص التغييرات كل دقيقة، على دفعات 50، بمؤشر توقيت التحقق ومعرفه. لا يبدأ باستيراد كامل التاريخ. عند فشل سجل لا تتقدم نقطة المعالجة عنه؛ راجع حالة المزامنة. البيانات المستلمة لقطة ثابتة؛ تغيير المصدر لاحقاً يحتاج تسوية موثقة ولا يستبدل حقول الحدث بصمت.

## إعدادات النشر

| الإعداد | الغرض |
| --- | --- |
| ConnectionStrings__Oms | اتصال حساب التشغيل بقاعدة PHEOC_OMS |
| ConnectionStrings__EgyptEbsReader | حساب القراءة المقيد للمصدر |
| Integration__Ebs__ApiKey | مفتاح الاستقبال، 32 حرفاً على الأقل |
| Integration__Ebs__CallbackUrl | عنوان HTTPS فعلي لإرسال حالة الحدث؛ غير مضبوط حالياً |
| Integration__Ebs__CallbackKey | اعتماد مزود رد الحالة عند الحاجة |
| Integration__EgyptEbs__SourceTimeZone | الافتراضي Egypt Standard Time؛ يراجع حسب المصدر |
| DataProtection__Path | مسار دائم لمفاتيح حماية البيانات؛ Windows DPAPI عند Windows |
| Storage__Attachments | مسار دائم للمرفقات خارج wwwroot |
| ASPNETCORE_ENVIRONMENT | Production للإنتاج؛ لا تعتمد على User Secrets في الإنتاج |

مفاتيح حماية البيانات ضرورية لقراءة رسائل Inbox المشفرة واستمرار الجلسات. تُنسخ بأمان مع بيانات التطبيق ويُختبر استرجاعها تحت هوية التشغيل نفسها، ولا تُحفظ في Git. ملفات `.local` مستبعدة صراحة من النشر.

## بناء حزمة Windows

```powershell
dotnet publish src/PHEOC.OMS.Web -c Release -r win-x64 --self-contained true -p:RuntimeFrameworkVersion=10.0.13 -o artifacts/publish
```

على IIS: مراجعة تحديثات Runtime/Hosting Bundle وSQL Server، تجهيز Application Pool وهوية محدودة ومسارات تخزين دائمة، ضبط الأسرار خارج web.config المتعقب، تفعيل HTTPS وشهادة صالحة، ثم اختبار الدخول والتفويض والمرفقات وSignalR بعد النشر. لا تضع إعداد Development أو HTTP المحلي في الإنتاج. الاتصال المحلي الحالي Encrypt=false لتوافق بيئة التطوير؛ يلزم اعتماد تشفير اتصال SQL مناسب في بيئة النشر.

## النسخ الاحتياطي والاستعادة

هذه خطة تشغيل، ولم يتم تنفيذ Backup/Restore فعلي في هذه المهمة: تحديد RPO/RTO والاحتفاظ والمسار من الجهة المسؤولة؛ Full backup للقاعدة ونسخ المرفقات والمفاتيح؛ نسخ سجلات المعاملات إذا اعتُمد Full recovery؛ تجربة استعادة معزولة والتحقق من الأحداث والمرفقات وInbox والصلاحيات؛ قياس زمن الاستعادة وتسجيله. SQL Agent 2016 كان متوقفاً أثناء فحص البيئة، لذلك لا توجد جدولة نسخ مؤكدة.

إعداد عنوان خادم EgyptEBS من الشاشة يحفظ في .local/settings/egypt-ebs-server.json بالنسبة إلى ContentRoot؛ احفظه عند تبديل حزمة النشر، وامنح هوية التطبيق حق الكتابة إليه. الملف لا يحتوي كلمة مرور ومستبعد من الحزمة، والحساب يبقى في Secrets/Environment. المخزن محلي لنسخة تطبيق واحدة. [تفاصيل الإعداد](EgyptEbsServerSettings.md).

إذا حُفظ حساب قراءة بديل من شاشة EgyptEBS، تحفظ بياناته مشفرة داخل إعداد الخادم المحلي. احفظ مفاتيح Data Protection وهوية تشغيل Windows عند تحديث التطبيق أو استعادته؛ يحتاج الحساب البديل هذه المفاتيح لفك التشفير. يمكن إدخال حساب بديل جديد أو إرجاع حساب إعداد التشغيل الأصلي من الشاشة عند الحاجة.

## ترقية QIRA

قبل تشغيل نسخة QIRA على قاعدة قائمة، راجع `database/003-Qira.sql` وطبّق الترقية صراحةً بواسطة `scripts/Update-QiraDatabase.ps1` (يطلب كلمة مرور إدارة SQL بأمان). يتحقق السكربت من قاعدة PHEOC_OMS وتاريخ الترقية السابقة، ويضيف ستة جداول فقط وحقوق حمايتها وصلاحيتي QIRA لمدير النظام. لا يعيد تهيئة القاعدة أو أسرار التشغيل ولا يعدل EgyptEBS. أُجريت هذه الترقية بالفعل على قاعدة التطوير الحالية. عند تهيئة قاعدة جديدة بـInitialize-Development تُدرج الترقية ضمن EF وتضاف الصلاحيات في Seed.

أرفق `docs/QiraSourceNotice.md` ومرجع المنهجية عند توزيع مادة QIRA المشتقة، وراعِ ترخيص المصدر. تحتاج الحسابات القائمة تسجيل خروج ودخول للحصول على claims جديدة. إعداد الأخطار والإجراءات من `/Qira/Configuration`؛ لا توجد قيم وطنية افتراضية. تظل المنهجية المحلية والتهيئة الوطنية بحاجة إلى اعتماد الجهة المختصة قبل الاستخدام التشغيلي المؤسسي.
